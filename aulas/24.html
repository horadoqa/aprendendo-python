Debugging em Python

Nesta aula, você vai aprender como encontrar, entender e corrigir erros em programas Python. Vamos conhecer os tracebacks, entender como utilizar um debugger e conhecer algumas estratégias práticas de depuração.

🐞 O que é Debugging?

Debugging, ou depuração, é o processo de encontrar e corrigir problemas em um programa.

Durante o desenvolvimento, é normal encontrar erros. O objetivo do debugging é descobrir onde o problema aconteceu, por que aconteceu e como corrigi-lo.

💡 Para lembrar:

Debugging não significa apenas corrigir o erro.

Significa entender o comportamento do programa até encontrar a causa do problema.

🔎 Tipos de erros

Antes de começar a depurar um programa, é importante saber que existem diferentes tipos de erros.

  • Erro de sintaxe — acontece quando o código não segue a sintaxe da linguagem.
  • Erro durante a execução — acontece enquanto o programa está sendo executado.
  • Erro lógico — o programa executa, mas produz um resultado incorreto.

✏️ Erro de sintaxe

Um erro de sintaxe acontece quando escrevemos algo que não está de acordo com as regras da linguagem Python.

sintaxe.py
1
2
3
4
nome = "Maria"
idade = 25
if idade >= 18
     print ( "Maior de idade" )
Terminal
! SyntaxError: expected ':'
💡 Dica:

Quando aparecer um SyntaxError, verifique principalmente a linha indicada e observe se existem dois-pontos, parênteses, aspas ou indentação incorretos.

📋 Entendendo os Tracebacks

Quando um erro acontece durante a execução, Python normalmente apresenta um traceback.

O traceback mostra informações importantes para descobrir onde o problema aconteceu.

💡 Um traceback pode mostrar:

• O arquivo onde ocorreu o problema.
• O número da linha.
• A sequência de chamadas de funções.
• O tipo da exceção.
• A mensagem relacionada ao erro.

🧪 Exemplo de Traceback

traceback.py
1
2
3
4
5
6
def dividir(a, b):
     return a / b
numero = dividir(10, 0)
print (numero)
Terminal
! Traceback (most recent call last):
! File "traceback.py", line 4
! numero = dividir(10, 0)
! File "traceback.py", line 2
! return a / b
! ZeroDivisionError: division by zero

Observe que o traceback mostra que o problema aconteceu dentro da função dividir() e indica a linha onde a divisão por zero ocorreu.

🧭 Como ler um Traceback

Ao encontrar um traceback, não é necessário entrar em pânico. Leia as informações com calma e siga o caminho apresentado pelo Python.

  • 1. Leia a última linha — normalmente ela mostra o tipo e a mensagem do erro.
  • 2. Procure o arquivo — identifique qual arquivo apresentou o problema.
  • 3. Observe o número da linha — vá até a linha indicada.
  • 4. Leia o código ao redor — o problema nem sempre está exatamente na linha apontada.
  • 5. Entenda a causa — antes de alterar o código, descubra por que o erro aconteceu.

🧠 Encontrando erros lógicos

Erros lógicos são especialmente interessantes porque o programa pode executar normalmente, sem apresentar nenhuma exceção.

O problema aparece no resultado.

logica.py
1
2
3
4
5
6
nota1 = 8
nota2 = 6
media = nota1 + nota2 / 2
print (media)
# Resultado inesperado: # 11.0

O código executa, mas a média esperada seria 7.0. O problema está na forma como a expressão foi escrita.

correcao.py
1
2
3
nota1 = 8
nota2 = 6
media = (nota1 + nota2) / 2
💡 Para lembrar:

Nem todo bug gera uma mensagem de erro.

Quando o resultado está errado, investigue também a lógica do programa.

🛠️ O que é um Debugger?

Um debugger é uma ferramenta que permite executar o programa de forma controlada para observar o que está acontecendo durante sua execução.

Em vez de executar todo o programa de uma vez, podemos pausar a execução em determinados pontos e analisar as variáveis.

💡 Pense no debugger como uma lupa:

Ele permite observar o programa passo a passo, verificando os valores das variáveis e o caminho que o código está seguindo.

⏸️ Breakpoints

Um breakpoint é um ponto onde queremos que o programa pause durante a execução.

Quando o programa chega ao breakpoint, podemos verificar os valores das variáveis antes de continuar.

breakpoint.py
1
2
3
4
5
6
nome = "Maria"
idade = 25
breakpoint ()
mensagem = f"Olá, {nome}!"
print (mensagem)

A função breakpoint() permite interromper a execução naquele ponto e iniciar a depuração utilizando o debugger disponível no ambiente Python.

👣 Executando passo a passo

Durante uma sessão de debugging, podemos avançar pelo código gradualmente.

  • Step Over — executa a próxima linha sem entrar nos detalhes internos de uma função.
  • Step Into — entra dentro da função que está sendo chamada.
  • Step Out — termina a execução da função atual e retorna para quem a chamou.
  • Continue — continua a execução até o próximo breakpoint.

📦 Observando variáveis

Uma das maiores vantagens de um debugger é conseguir observar o valor das variáveis enquanto o programa está sendo executado.

🧠 Estratégias de depuração

Não existe apenas uma maneira de fazer debugging. Uma boa estratégia é investigar o problema de forma organizada.

  • Reproduza o problema — confirme que consegue provocar o erro.
  • Leia a mensagem de erro — não ignore o traceback.
  • Identifique o ponto da falha — descubra onde o comportamento começou a ficar diferente do esperado.
  • Verifique os dados — confirme os valores das variáveis.
  • Divida o problema — investigue pequenas partes do código.
  • Faça uma alteração por vez — isso facilita descobrir qual mudança resolveu o problema.
  • Teste novamente — confirme se o problema realmente foi corrigido.

🔬 Estratégia prática

Uma maneira simples de organizar o processo de debugging é seguir cinco etapas:

1️⃣ Reproduzir
Faça o erro acontecer novamente.

2️⃣ Observar
Leia o erro e analise os valores.

3️⃣ Isolar
Encontre a menor parte do código responsável pelo problema.

4️⃣ Corrigir
Faça a alteração necessária.

5️⃣ Validar
Execute novamente e confirme o comportamento.

🧪 Debugging no QA

Para quem trabalha com QA e automação de testes, debugging é uma habilidade fundamental.

Quando um teste automatizado falha, o problema pode estar no sistema testado, nos dados, na configuração do ambiente ou no próprio código do teste.

💡 Pense como QA:

Um teste falhou.

Antes de alterar o código aleatoriamente, pergunte:

• Qual teste falhou?
• Em qual linha ocorreu o erro?
• Qual era o valor esperado?
• Qual foi o valor recebido?
• O problema acontece sempre?
• O problema está no teste ou na aplicação?

✅ Boas práticas de Debugging

  • Leia o erro antes de modificar o código.
  • Tente reproduzir o problema.
  • Faça pequenas alterações por vez.
  • Utilize mensagens temporárias com print() quando necessário.
  • Utilize breakpoints para investigar comportamentos mais complexos.
  • Verifique os valores das variáveis.
  • Depois da correção, execute novamente os testes para garantir que o problema foi realmente resolvido.
  • Evite simplesmente "fazer o erro desaparecer". Procure entender a causa.
