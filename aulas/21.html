Pacotes em Python

Nesta aula, você vai aprender como organizar projetos Python utilizando pacotes. Vamos entender como estruturar pastas, conhecer o arquivo __init__.py e aprender como organizar módulos de forma mais profissional.

📦 O que são pacotes?

Um pacote é uma forma de organizar vários módulos Python dentro de uma mesma estrutura de pastas. Enquanto um módulo normalmente é um arquivo .py, um pacote pode reunir vários módulos relacionados.

💡 Para lembrar:

Pense em um módulo como um arquivo que contém funcionalidades.

Um pacote é como uma pasta que organiza vários módulos que possuem alguma relação entre si.

🧩 Módulo x Pacote

É importante diferenciar esses dois conceitos.

  • Módulo — normalmente é um arquivo Python, como validacoes.py.
  • Pacote — é uma estrutura de diretórios utilizada para organizar módulos relacionados.
Exemplo:

validacoes.py é um módulo.

Já uma pasta como:

validacoes/ pode ser utilizada como um pacote para organizar vários módulos de validação.

📁 Estrutura de pastas

Em projetos pequenos, podemos ter poucos arquivos. Conforme o projeto cresce, porém, é importante separar as responsabilidades em diferentes pastas e arquivos.

Um projeto de automação de testes, por exemplo, pode ter uma estrutura como esta:

projeto_qa/
├── main.py
│
├── testes/
│   ├── __init__.py
│   ├── teste_login.py
│   └── teste_cadastro.py
│
├── validacoes/
│   ├── __init__.py
│   └── respostas.py
│
└── dados/
    ├── __init__.py
    └── usuarios.py

Dessa forma, cada pasta possui uma responsabilidade específica.

  • testes/ — contém os testes.
  • validacoes/ — contém funções relacionadas às validações.
  • dados/ — contém dados ou funções relacionadas aos dados utilizados nos testes.

🧱 __init__.py

O arquivo __init__.py é um arquivo especial utilizado dentro de pacotes Python. Ele pode ser utilizado para inicializar o pacote e também para organizar quais recursos queremos disponibilizar por meio dele.

💡 Importante:

Em versões modernas do Python, uma pasta pode funcionar como pacote mesmo sem um arquivo __init__.py em alguns cenários.

Porém, o __init__.py continua sendo muito utilizado em projetos por deixar explícita a intenção de tratar aquela pasta como um pacote e permitir inicializações e imports organizados.

💻 Exemplo de __init__.py

Imagine que temos um pacote chamado validacoes:

🎯 Importando diretamente do pacote

Também podemos organizar o __init__.py para permitir que determinadas funções sejam importadas diretamente pelo pacote.

Por exemplo, imagine a seguinte estrutura:

projeto_qa/
├── main.py
└── validacoes/
    ├── __init__.py
    └── respostas.py

No arquivo __init__.py podemos escrever:

🗂️ Subpacotes

Um pacote também pode conter outros pacotes. Isso é útil em projetos maiores, onde precisamos organizar ainda mais as funcionalidades.

projeto_qa/
├── main.py
│
├── testes/
│   ├── __init__.py
│   └── api/
│       ├── __init__.py
│       └── teste_login.py
│
└── utils/
    ├── __init__.py
    └── dados.py

Nesse exemplo, api é um subpacote dentro do pacote testes.

🧪 Organização de um projeto de QA

Em automação de testes, uma boa organização de pastas facilita bastante a manutenção do projeto. Uma estrutura possível é:

automacao_qa/
│
├── testes/
│   ├── __init__.py
│   ├── login/
│   │   ├── __init__.py
│   │   └── teste_login.py
│   │
│   └── cadastro/
│       ├── __init__.py
│       └── teste_cadastro.py
│
├── utils/
│   ├── __init__.py
│   ├── validacoes.py
│   └── dados.py
│
└── main.py

Uma estrutura como essa permite separar os testes por funcionalidade e manter funções auxiliares em um local específico.

💡 Pense como QA:

Um projeto de testes pode crescer rapidamente.

Separar testes, dados e funções auxiliares em pacotes ajuda a encontrar os arquivos com mais facilidade e reduz a duplicação de código.

✅ Boas práticas

Ao organizar projetos Python, algumas práticas ajudam a manter o código mais limpo e fácil de entender.

  • Organize arquivos por responsabilidade.
  • Evite colocar todo o código em um único arquivo.
  • Utilize nomes claros para arquivos e pastas.
  • Evite duplicar funções que podem ser reutilizadas.
  • Utilize módulos e pacotes para separar funcionalidades relacionadas.
  • Mantenha uma estrutura de projeto simples e consistente.

🚀 Desafio

Crie um pequeno projeto de automação de QA utilizando pacotes. Sua estrutura deverá conter:

  • Um pacote chamado testes.
  • Um pacote chamado utils.
  • Um arquivo validacoes.py dentro de utils.
  • Um arquivo teste_login.py dentro de testes.
  • Um __init__.py em cada pacote.
