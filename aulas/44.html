HTTP

Nesta aula, você vai aprender os principais conceitos do HTTP, o protocolo utilizado para comunicação entre clientes e servidores na web.

Vamos entender o que são requests e responses, conhecer os métodos GET, POST, PUT e DELETE, além dos principais status codes.

💡 Para lembrar:

Quando você acessa uma página, envia um formulário ou utiliza uma API, normalmente existe uma comunicação HTTP acontecendo entre um cliente e um servidor.

🌐 O que é HTTP?

HTTP significa HyperText Transfer Protocol. É um protocolo utilizado para comunicação na web.

De forma simplificada, um cliente envia uma request para um servidor e o servidor retorna uma response.

🔄 Comunicação HTTP:

Cliente → Request → Servidor

Servidor → Response → Cliente

📤 Request

Uma request é uma requisição enviada pelo cliente para o servidor.

O cliente pode solicitar dados, enviar informações, alterar recursos ou excluir dados.

Uma requisição HTTP pode conter informações como:

  • Método HTTP.
  • URL.
  • Headers.
  • Parâmetros.
  • Body, quando necessário.
request.txt
1

GET /usuarios HTTP/1.1
Host: exemplo.com
Accept: application/json

📥 Response

A response é a resposta enviada pelo servidor depois de receber uma request.

Uma resposta normalmente possui um status code, headers e, dependendo da situação, um conteúdo no body.

Content-Type: application/json
{
   "nome": "Maria"
💡 Resumindo:

Request → pedido feito pelo cliente.

Response → resposta enviada pelo servidor.

🔎 GET

O método GET é utilizado principalmente para solicitar ou consultar informações de um servidor.

Por exemplo, podemos utilizar GET para buscar uma lista de usuários.

get.py
1
2
3
4
import requests
resposta = requests.get( "https://api.exemplo.com/usuarios" )
print( resposta.status_code)
🎯 GET no QA:

Em testes de API, GET é muito utilizado para verificar se determinados recursos podem ser consultados corretamente.

📤 POST

O método POST é utilizado normalmente para enviar dados ao servidor e criar um novo recurso.

post.py
1
2
3
4
5
6
import requests
dados = {
   "nome": "Maria"
}
resposta = requests.post( "https://api.exemplo.com/usuarios" , json=dados)

O conteúdo enviado ao servidor geralmente fica no body da requisição.

✏️ PUT

O método PUT é utilizado para atualizar um recurso existente.

Por exemplo, podemos atualizar os dados de um usuário identificado pelo número 10.

put.py
1
2
3
4
5
6
import requests
dados = {
   "nome": "Maria Silva"
}
resposta = requests.put( "https://api.exemplo.com/usuarios/10" , json=dados)

🗑️ DELETE

O método DELETE é utilizado para solicitar a remoção de um recurso.

delete.py
1
2
3
import requests
resposta = requests.delete( "https://api.exemplo.com/usuarios/10" )
🧠 Os quatro métodos:

GET → consultar.

POST → criar/enviar.

PUT → atualizar.

DELETE → remover.

🚦 Status codes

O servidor utiliza status codes para informar o resultado de uma requisição.

Os códigos são divididos em grupos de acordo com o primeiro número.

  • 1xx — informações.
  • 2xx — sucesso.
  • 3xx — redirecionamento.
  • 4xx — erro relacionado à requisição do cliente.
  • 5xx — erro no servidor.

📊 Principais status codes

200 OK
A requisição foi processada com sucesso.

201 Created
Um novo recurso foi criado.

204 No Content
A requisição foi processada com sucesso, mas não há conteúdo para retornar.

400 Bad Request
A requisição possui algum problema.

401 Unauthorized
A requisição não possui autenticação válida.

403 Forbidden
O servidor entendeu a requisição, mas não permite o acesso ao recurso.

404 Not Found
O recurso solicitado não foi encontrado.

500 Internal Server Error
O servidor encontrou um erro interno.

🧪 Verificando um status code

Em automação de testes, podemos verificar diretamente o status retornado pela API.

teste_api.py
1
2
3
4
5
6
import requests
resposta = requests.get( "https://api.exemplo.com/usuarios/1" )
assert resposta.status_code == 200
🎯 No QA:

O status code é uma das primeiras informações que podemos verificar ao testar uma API.

Por exemplo, uma consulta bem-sucedida pode esperar 200, enquanto a criação de um recurso pode esperar 201.

🔄 Request e Response na prática

Imagine que um teste precisa consultar um usuário. O fluxo pode ser representado assim:

1️⃣ Cliente
Envia um GET para /usuarios/10.

↓

2️⃣ Servidor
Processa a requisição.

↓

3️⃣ Response
Retorna 200 OK e os dados do usuário.

↓

4️⃣ Teste
Verifica se o status e os dados estão corretos.

📝 Exercício

Imagine uma API de usuários. Identifique qual método HTTP seria mais adequado para cada operação:

  • Consultar todos os usuários.
  • Criar um novo usuário.
  • Atualizar os dados de um usuário.
  • Excluir um usuário.
💡 Resposta:

Consultar → GET

Criar → POST

Atualizar → PUT

🧠 Resumo da aula

O que você aprendeu:

• HTTP é um protocolo utilizado para comunicação entre clientes e servidores.
• Request é a requisição enviada pelo cliente.
• Response é a resposta enviada pelo servidor.
• GET é utilizado principalmente para consultar recursos.
• POST é utilizado principalmente para criar ou enviar dados.
• PUT é utilizado para atualizar recursos.
• DELETE é utilizado para remover recursos.
• Status codes indicam o resultado da requisição.
• 2xx representa sucesso.
• 4xx representa erros relacionados à requisição.
• 5xx representa erros no servidor.
• Em QA, status codes e conteúdo da response são informações importantes para validar APIs.
