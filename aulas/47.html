APIs com FastAPI

Nesta aula, você vai aprofundar seus conhecimentos sobre criação de APIs utilizando FastAPI. Vamos aprender como implementar um CRUD, validar dados recebidos pela API e utilizar a documentação automática fornecida pelo framework.

💡 Para lembrar:

Na aula anterior aprendemos a criar rotas, endpoints e respostas JSON.

Agora vamos construir uma API mais completa, capaz de criar, consultar, atualizar e excluir dados.

🔄 O que é CRUD?

CRUD é uma sigla utilizada para representar as quatro operações básicas realizadas sobre dados de uma aplicação.

C — Create
Criar um novo registro.

R — Read
Consultar registros existentes.

U — Update
Atualizar um registro.

D — Delete
Excluir um registro.

Em uma API REST, essas operações normalmente são relacionadas aos métodos HTTP:

POST → Create

GET → Read

PUT → Update

DELETE → Delete

✅ Validação de dados

Uma API precisa verificar se os dados recebidos estão corretos antes de utilizá-los.

O FastAPI utiliza Pydantic para facilitar a validação dos dados.

Podemos criar um modelo definindo quais campos esperamos receber e quais tipos eles devem possuir.

models.py

from pydantic import BaseModel
class Produto(BaseModel):
     nome: str
     preco: float

Agora podemos utilizar o modelo no endpoint para receber um produto validado.

     }

⚠️ O que acontece quando os dados são inválidos?

Se o cliente enviar um valor incompatível com o modelo esperado, o FastAPI realiza a validação e retorna uma resposta indicando o erro.

Exemplo:

A API espera:

"preco": 49.90

Mas recebe:

"preco": "abc"

O dado não corresponde ao tipo esperado e a validação falha.

📚 Documentação automática

Uma das grandes vantagens do FastAPI é a geração automática de documentação da API.

A partir das rotas e modelos definidos no código, o FastAPI consegue gerar uma documentação interativa.

📖 Swagger UI

A documentação interativa normalmente pode ser acessada através de:

/docs

Nela podemos visualizar os endpoints e até mesmo executar requisições diretamente pelo navegador.
📘 ReDoc

O FastAPI também disponibiliza uma interface de documentação através de:

/redoc

Essa interface apresenta a documentação da API de outra forma, facilitando a consulta dos endpoints.

🖥️ Documentação na prática

Depois de iniciar uma aplicação FastAPI, podemos acessar a documentação pelo navegador.

🧱 Estrutura de um CRUD

Um CRUD completo de produtos pode possuir endpoints semelhantes aos seguintes:

GET /produtos
Lista todos os produtos.

GET /produtos/{id}
Busca um produto específico.

POST /produtos
Cria um novo produto.

PUT /produtos/{id}
Atualiza um produto.

DELETE /produtos/{id}
Exclui um produto.

🧪 FastAPI para QA

Para quem trabalha com QA, o FastAPI facilita bastante a visualização e execução de testes de uma API.

A documentação automática permite identificar rapidamente:

  • Quais endpoints existem.
  • Quais métodos HTTP são utilizados.
  • Quais parâmetros são necessários.
  • Quais dados devem ser enviados.
  • Quais tipos de dados são esperados.
  • Quais respostas podem ser retornadas.
🎯 Pense como QA:

Ao testar um endpoint de criação, não teste apenas um cadastro válido.

Teste também:

• Campos obrigatórios ausentes.
• Tipos incorretos.
• Valores inválidos.
• Dados duplicados.
• IDs inexistentes.
• Payloads incompletos.
