Encapsulamento

Nesta aula, você vai aprender o conceito de encapsulamento na Programação Orientada a Objetos. Vamos entender a diferença entre atributos públicos e privados e conhecer as properties do Python.

🔒 O que é encapsulamento?

Encapsulamento é uma técnica da Programação Orientada a Objetos que ajuda a controlar como os dados de um objeto podem ser acessados e modificados.

A ideia é proteger o estado interno do objeto e controlar as alterações realizadas nesses dados.

💡 Para lembrar:

Encapsular significa controlar o acesso aos dados internos de um objeto.

Em vez de permitir que qualquer parte do programa altere um valor livremente, podemos criar regras para controlar essa alteração.

🌐 Atributos públicos

Por padrão, os atributos criados em Python podem ser acessados diretamente através do objeto.

Esses atributos são considerados públicos.

Nesse exemplo, o atributo nome pode ser acessado e alterado diretamente.

⚠️ Atenção:

Embora essa liberdade possa ser útil em alguns casos, ela também permite que valores importantes sejam alterados sem nenhuma validação.

🔐 Atributos privados

Em Python, podemos indicar que um atributo deve ser tratado como interno utilizando dois underscores (__) no início do nome.

Esse recurso é chamado de name mangling. Ele dificulta o acesso direto ao atributo e ajuda a proteger os dados internos da classe.

     def __init__ ( self , saldo):
         self .__saldo = saldo
conta = Conta(1000)
print ( conta._Conta__saldo)
# O acesso direto não é recomendado
💡 Importante:

O uso de __ em Python não cria um atributo verdadeiramente privado como em algumas outras linguagens.

Ele utiliza name mangling para dificultar o acesso direto ao atributo e indicar que aquele dado deve ser tratado como interno.

🔄 Controlando o acesso aos atributos

Uma maneira de controlar o acesso aos dados é utilizar métodos para ler e modificar os atributos.

Esses métodos são tradicionalmente chamados de getters e setters.

✨ Properties

O Python oferece uma forma mais elegante de controlar atributos utilizando properties.

Com @property, podemos acessar um método como se ele fosse um atributo. Isso permite manter uma interface simples para quem utiliza a classe, enquanto continuamos controlando o acesso aos dados internamente.

class Produto:

         self .__preco = preco
     @property
     def preco ( self ):
         return self .__preco
     @preco.setter
     def preco ( self , valor):
         if valor >= 0:
             self .__preco = valor
produto = Produto(100)
produto.preco = 150

👀 Lendo uma property

Quando utilizamos @property, podemos acessar o método como se estivéssemos acessando um atributo comum.

exemplo.py
1
2
3
produto = Produto(100)
print ( produto.preco)
produto.preco = 200

Perceba que não precisamos chamar produto.preco(). A property permite utilizar simplesmente produto.preco.

🧠 A ideia:

Para quem utiliza o objeto:

produto.preco

parece um atributo comum.

Internamente, porém, podemos executar regras para controlar como esse valor é lido ou alterado.

🛡️ Validando valores

Uma das grandes vantagens das properties é poder adicionar regras de validação antes de alterar um atributo.

class Conta:
     def __init__ ( self , saldo):
         self .__saldo = saldo
     @property
     def saldo ( self ):
         return self .__saldo
     @saldo.setter
     def saldo ( self , valor):
         if valor < 0:
             raise ValueError ( "Saldo não pode ser negativo" )
         self .__saldo = valor
conta = Conta(1000)

Agora o programa consegue impedir que um valor inválido seja atribuído ao saldo.

🎯 Regra de negócio:

O atributo saldo não deve aceitar valores negativos.

A property permite colocar essa regra dentro da própria classe.

🧪 Encapsulamento no QA

O encapsulamento é especialmente útil em automação de testes quando precisamos proteger dados ou garantir que determinadas regras sejam respeitadas.

Por exemplo, uma classe de usuário pode controlar como o email é alterado, evitando que um valor inválido seja armazenado.

class UsuarioTeste:
     def __init__ ( self , email):
         self .__email = email
     @property
     def email ( self ):
         return self .__email
     @email.setter
     def email ( self , valor):
         if "@" not in valor:
             raise ValueError ( "Email inválido" )
         self .__email = valor
usuario = UsuarioTeste( "maria@email.com" )

🧠 Resumo da aula

O que você aprendeu:

• Encapsulamento ajuda a controlar o acesso aos dados de um objeto.
• Atributos públicos podem ser acessados diretamente.
• O prefixo __ ativa o name mangling.
• Atributos com __ devem ser tratados como detalhes internos da classe.
• Getters permitem controlar a leitura de um atributo.
• Setters permitem controlar sua alteração.
• @property permite acessar um método como se fosse um atributo.
• Properties são úteis para aplicar validações e regras de negócio.
• Encapsulamento ajuda a tornar o código mais organizado, seguro e previsível.
