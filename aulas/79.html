Performance

Nesta aula, vamos aprender como analisar e melhorar o desempenho de programas Python. Vamos conhecer conceitos importantes como profiling, complexidade de algoritmos e otimização.

🎯 Objetivo da aula:

Aprender a identificar partes lentas de um programa, compreender a complexidade dos algoritmos e aplicar técnicas de otimização de forma consciente.

⚡ O que é performance?

Performance representa a eficiência com que um programa executa suas tarefas. Um programa pode produzir o resultado correto e ainda assim apresentar uma performance ruim.

Quando falamos de performance, podemos analisar diferentes aspectos:

  • Tempo de execução.
  • Consumo de memória.
  • Uso de CPU.
  • Uso de recursos externos.
  • Quantidade de operações realizadas.
💡 Ideia principal:

Antes de otimizar um programa, precisamos descobrir onde realmente está o problema.

🔍 Primeiro medir, depois otimizar

Uma das regras mais importantes de performance é:

Medir → Identificar o problema → Otimizar → Medir novamente

Fazer alterações no código apenas por "parecer mais rápido" pode gerar código mais complexo sem trazer uma melhoria real.

Por isso utilizamos ferramentas de medição e profiling.

⏱️ Medindo o tempo de execução

Uma maneira simples de analisar performance é medir quanto tempo uma operação demora. O módulo time pode ser utilizado para isso.

Ele é apropriado para medir intervalos de tempo durante a execução de programas.

🔬 2. Profiling

Profiling é o processo de analisar detalhadamente onde um programa está gastando seu tempo e seus recursos.

Em vez de analisar o programa inteiro manualmente, podemos utilizar ferramentas que mostram quais funções estão consumindo mais tempo.

🎯 Objetivo do profiling:

Descobrir os chamados gargalos do programa.

🐍 cProfile

O Python possui uma ferramenta de profiling integrada chamada cProfile.

programa.py
1
2
3
4
5
6
def calcular():
     total = 0
     for i in range(1000000):
         total += i
     return total
calcular()

Podemos executar o programa utilizando:

terminal
1
python -m cProfile programa.py

O resultado apresenta informações sobre chamadas de funções e o tempo gasto em cada uma delas.

💡 Exemplo de análise:

Se uma função representa uma grande parte do tempo total de execução, ela pode ser um bom candidato para investigação e possível otimização.

📈 3. Complexidade de algoritmos

Uma das formas mais importantes de analisar um algoritmo é estudar sua complexidade.

A complexidade ajuda a entender como o custo de um algoritmo cresce conforme aumentamos a quantidade de dados.

Complexidade não é exatamente o tempo em segundos.

Ela descreve como o número de operações cresce em relação ao tamanho da entrada.

🧮 Big O

A notação Big O é utilizada para representar a complexidade de um algoritmo.

Algumas complexidades comuns são:

  • O(1) — constante.
  • O(log n) — logarítmica.
  • O(n) — linear.
  • O(n log n) — comum em algoritmos eficientes de ordenação.
  • O(n²) — quadrática.
  • O(2ⁿ) — exponencial.
💡 Regra geral:

Quanto mais rapidamente a complexidade cresce, mais difícil tende a ser lidar com entradas grandes.

🟢 O(1) — Constante

Uma operação de complexidade O(1) possui custo aproximadamente constante em relação ao tamanho da entrada.

constante.py
1
2
3
numeros = [10, 20, 30, 40]
primeiro = numeros[0]

🔵 O(n) — Linear

Um algoritmo O(n) normalmente percorre os elementos da entrada uma vez.

linear.py
1
2
3
4
numeros = [1, 2, 3, 4, 5]
for numero in numeros:
     print(numero)

Se a lista possuir n elementos, o loop será executado aproximadamente n vezes.

5 elementos → aproximadamente 5 operações
1.000 elementos → aproximadamente 1.000 operações

🔴 O(n²) — Quadrática

Quando temos dois loops aninhados que percorrem a mesma entrada, frequentemente temos uma complexidade O(n²).

quadratica.py
1
2
3
4
5
numeros = [1, 2, 3, 4, 5]
for a in numeros:
     for b in numeros:
         print(a, b)

Para cada elemento de n, percorremos novamente aproximadamente n elementos. Portanto:

n × n = n²

🚀 4. Otimização

Otimizar significa modificar um programa para melhorar seu desempenho, mantendo seu comportamento correto.

Existem várias estratégias possíveis.

  • Escolher algoritmos melhores.
  • Utilizar estruturas de dados adequadas.
  • Evitar cálculos desnecessários.
  • Evitar trabalho repetido.
  • Utilizar recursos da biblioteca padrão.
  • Reduzir operações dentro de loops.
  • Utilizar profiling para encontrar gargalos.

📦 Estruturas de dados e performance

A escolha da estrutura de dados pode ter grande impacto na performance. Por exemplo, procurar um elemento em uma lista geralmente exige percorrer seus elementos.

lista.py
1
2
3
numeros = list(range(100000))
print(99999 in numeros)

Para testes de pertencimento frequentes, um set pode ser mais apropriado:

conjunto.py
1
2
3
numeros = set(range(100000))
print(99999 in numeros)
💡 Importante:

A estrutura correta depende do problema. Performance não significa simplesmente escolher a estrutura "mais rápida", mas escolher a estrutura adequada para a operação que será realizada.

♻️ Evitando cálculos repetidos

Um erro comum é realizar várias vezes um cálculo que poderia ser feito apenas uma vez.

repeticao.py
1
2
3
4
5
6
numeros = range(1000)
total = sum(numeros)
for i in range(10):
     print(total)

O valor de total é calculado uma única vez e depois reutilizado.

🧠 Código Python idiomático

Algumas construções da linguagem Python permitem escrever operações de forma mais clara e eficiente. Um exemplo são as list comprehensions.

comprehension.py
1
2
3
numeros = range(10)
quadrados = [x ** 2 for x in numeros]

Entretanto, escrever menos código não significa automaticamente que o código será mais rápido. A prioridade deve ser manter o código correto, legível e adequado ao problema.

🌱 Geradores e memória

Em situações que envolvem grandes quantidades de dados, podemos evitar armazenar tudo na memória de uma vez. Geradores podem produzir valores sob demanda.

gerador.py
1
2
3
4
5
def numeros():
     for i in range(1000000):
         yield i
for numero in numeros():
Geradores podem ajudar a reduzir o consumo de memória quando os dados podem ser processados gradualmente.

⚠️ Cuidado com otimização prematura

Existe uma frase muito conhecida na área de desenvolvimento: "Não otimize antes de medir."

Uma otimização pode tornar o código mais difícil de entender e manter. Se ela não resolver um problema real de performance, pode não valer a pena.

🎯 Prioridade:

1. Código correto
2. Código legível
3. Código testado
4. Medir performance
5. Otimizar gargalos reais

🚀 Exemplo completo de análise

Vamos criar duas funções que verificam se existem elementos repetidos em uma lista.

performance.py

def possui_duplicados(lista):
     for i in range(len(lista)):
         for j in range(i + 1, len(lista)):
             if lista[i] == lista[j]:
                 return True
     return False
def possui_duplicados_rapido(lista):
     return len(lista) != len(set(lista))
numeros = [1, 2, 3, 4, 3]
print(possui_duplicados(numeros))
print(possui_duplicados_rapido(numeros))

A primeira implementação compara diversos pares de elementos e possui complexidade aproximadamente O(n²).

A segunda utiliza um set e pode reduzir significativamente o trabalho em muitos cenários.

💡 Lição:

Muitas vezes, uma grande melhoria de performance vem da escolha de um algoritmo ou estrutura de dados melhor, e não de pequenas alterações na sintaxe.

🧠 Performance e memória

Performance não significa apenas velocidade. Um programa também pode consumir muita memória.

Podemos utilizar ferramentas como tracemalloc para investigar o uso de memória em programas Python.

✅ Boas práticas de performance

  • Meça antes de otimizar.
  • Use profiling para encontrar gargalos.
  • Escolha algoritmos adequados.
  • Escolha estruturas de dados adequadas.
  • Evite cálculos desnecessários.
  • Evite processamento repetido.
  • Considere o consumo de memória.
  • Prefira código simples e legível.
  • Faça testes depois das otimizações.
