Boas práticas em Python

Escrever código que funciona é apenas uma parte do desenvolvimento de software. Nesta aula, você vai aprender algumas boas práticas que ajudam a criar códigos mais legíveis, organizados, reutilizáveis e fáceis de manter.

Vamos conhecer conceitos como PEP 8, código legível, DRY, SOLID e organização de projetos.

💡 Para lembrar:

Um bom código não deve apenas funcionar. Ele também deve ser fácil de entender, modificar, testar e reutilizar.

📐 PEP 8

A PEP 8 é o principal guia de estilo para código Python. Ela apresenta recomendações para manter o código consistente e fácil de ler.

Algumas recomendações comuns incluem:

  • Utilizar 4 espaços para indentação.
  • Utilizar nomes de variáveis claros.
  • Utilizar snake_case para funções e variáveis.
  • Utilizar PascalCase para classes.
  • Evitar linhas excessivamente longas.
  • Separar adequadamente funções e classes.

♻️ DRY

DRY significa Don't Repeat Yourself, ou seja, "não se repita".

A ideia é evitar duplicação desnecessária de código. Quando uma mesma regra aparece em vários lugares, podemos centralizá-la em uma função ou estrutura reutilizável.

🧱 SOLID

SOLID é um conjunto de cinco princípios utilizados para criar software mais organizado, flexível e fácil de manter.

  • S — Single Responsibility
    Uma classe ou função deve ter uma única responsabilidade principal.
  • O — Open/Closed
    O código deve estar aberto para extensão, mas fechado para modificações desnecessárias.
  • L — Liskov Substitution
    Objetos de uma classe filha devem poder ser utilizados onde a classe pai é esperada.
  • I — Interface Segregation
    É melhor ter interfaces menores e específicas do que uma interface grande e genérica.
  • D — Dependency Inversion
    O código deve depender de abstrações em vez de implementações concretas sempre que fizer sentido.
💡 Para começar:

Você não precisa decorar os cinco princípios imediatamente. O mais importante é entender que SOLID busca diminuir acoplamento e facilitar a manutenção do software.

✅ Checklist de boas práticas

  • Utilizar nomes de variáveis e funções significativos.
  • Seguir as recomendações da PEP 8.
  • Evitar duplicação de código.
  • Criar funções pequenas e com responsabilidades claras.
  • Manter arquivos e pastas organizados.
  • Escrever testes fáceis de entender.
  • Utilizar princípios SOLID quando fizer sentido.
  • Priorizar código simples e legível.
