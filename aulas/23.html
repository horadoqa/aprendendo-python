Criando exceções em Python

Nesta aula, você vai aprender como criar e disparar suas próprias exceções utilizando raise. Também vamos aprender a criar exceções personalizadas para representar situações específicas da aplicação.

🚨 O que é raise?

Até agora, aprendemos como tratar exceções utilizando try e except. Porém, também podemos criar uma exceção manualmente quando uma determinada condição não for válida.

Para isso, utilizamos a palavra-chave raise.

💡 Para lembrar:

raise significa, basicamente:

"Python, pare a execução neste ponto e informe que aconteceu uma situação de erro."

💻 Usando raise

Podemos utilizar raise para impedir que uma operação continue quando uma condição inválida for encontrada.

raise.py

idade = 15
if idade < 18:
     raise ValueError( "Idade mínima é 18 anos." )
print ( "Acesso permitido." )
Terminal
! ValueError: Idade mínima é 18 anos.
💡 Importante:

Quando o raise é executado, o Python interrompe a execução naquele ponto e dispara a exceção.

Por isso, o print() depois do raise não será executado nesse exemplo.

🛡️ Usando raise com try e except

Uma exceção criada com raise também pode ser capturada utilizando try e except.

🧩 Exceções personalizadas

Python possui várias exceções prontas, como ValueError, TypeError e FileNotFoundError. Porém, em projetos maiores, podemos precisar representar situações específicas da nossa aplicação.

Para isso, podemos criar uma exceção personalizada.

Uma exceção personalizada normalmente é criada utilizando uma classe que herda de Exception.

💡 Para lembrar:

Uma exceção personalizada é uma classe criada por nós para representar um tipo específico de problema.

🏗️ Criando nossa própria exceção

Vamos criar uma exceção chamada IdadeInvalidaError.

class IdadeInvalidaError( Exception):

idade = -5
if idade < 0:
     raise IdadeInvalidaError( "A idade não pode ser negativa." )

🔧 Exceções dentro de funções

É muito comum utilizar raise dentro de funções para validar os dados recebidos.

Dessa forma, a função pode informar ao código que a chamou que uma determinada regra não foi atendida.

     print (erro)

🧪 Exceções personalizadas no QA

Em automação de testes, exceções personalizadas podem deixar o código mais claro e facilitar a identificação de falhas.

Por exemplo, podemos criar uma exceção específica para indicar que um teste não encontrou o resultado esperado.

class TesteFalhouError( Exception):
     pass
resultado = False
if not resultado:
     raise TesteFalhouError( "O resultado esperado não foi encontrado." )
💡 Pense como QA:

Uma exceção personalizada pode deixar uma falha muito mais fácil de entender.

Em vez de simplesmente indicar que "algo deu errado", podemos criar uma exceção que explique exatamente qual regra do teste não foi atendida.

✅ Boas práticas

  • Utilize raise quando uma regra importante não for atendida.
  • Escolha nomes claros para suas exceções personalizadas.
  • Faça suas exceções personalizadas herdarem de Exception.
  • Não crie uma exceção personalizada para situações que já possuem uma exceção adequada no Python.
  • Utilize mensagens claras para facilitar a identificação do problema.
  • Combine raise com try e except quando precisar disparar e tratar uma exceção.
