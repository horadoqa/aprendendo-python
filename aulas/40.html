Git e GitHub

Nesta aula, você vai aprender os principais conceitos do Git e do GitHub. Vamos entender o que são repositórios, commits, branches, merges e pull requests.

Essas ferramentas são fundamentais no desenvolvimento de software e também fazem parte da rotina de profissionais de QA, principalmente em projetos de automação de testes.

💡 Para lembrar:

O Git é um sistema de controle de versão.

O GitHub é uma plataforma que permite hospedar repositórios Git e colaborar com outras pessoas.

🧠 O que é Git?

O Git é uma ferramenta de controle de versão. Ele permite acompanhar as alterações feitas nos arquivos de um projeto ao longo do tempo.

Imagine que você está desenvolvendo um projeto de automação de testes. Durante o desenvolvimento, você pode criar novos testes, corrigir bugs e modificar arquivos. O Git registra essas alterações e permite consultar o histórico do projeto.

✅ Com Git podemos:

• Registrar alterações.
• Consultar o histórico do projeto.
• Criar versões do código.
• Trabalhar em diferentes funcionalidades.
• Colaborar com outras pessoas.
• Recuperar versões anteriores do código.

☁️ O que é GitHub?

O GitHub é uma plataforma online utilizada para hospedar repositórios Git e facilitar a colaboração entre desenvolvedores e equipes.

Um projeto pode existir localmente no computador e também ser enviado para um repositório no GitHub.

💡 Git x GitHub

Git → ferramenta de controle de versão.

GitHub → plataforma para hospedar repositórios Git e colaborar com outras pessoas.

📦 Repositórios

Um repositório é o local onde o projeto e seu histórico de versões são armazenados.

Podemos criar um repositório local utilizando:

Terminal
1
git init

O comando git init inicializa um novo repositório Git na pasta atual.

🔎 Verificando alterações

O comando git status mostra o estado atual do repositório.

Terminal
1
git status

Esse comando é muito útil para verificar quais arquivos foram modificados, adicionados ou ainda não estão sendo rastreados pelo Git.

💾 Commit

Um commit representa um registro das alterações realizadas no projeto.

Antes de criar um commit, precisamos adicionar os arquivos à área de preparação do Git.

Terminal
1
2
git add .
git commit -m "Adiciona testes de login"

O comando git add adiciona alterações à área de preparação. Depois, git commit registra essas alterações no histórico.

💡 Boa prática:

Escreva mensagens de commit claras e objetivas.

Exemplo:
git commit -m "Adiciona teste de login"

📜 Histórico de commits

Podemos visualizar o histórico de commits utilizando o comando:

Terminal
1
git log

Para visualizar um histórico mais resumido:

Terminal
1
git log --oneline

🌿 Branch

Uma branch é uma linha independente de desenvolvimento.

Branches permitem desenvolver uma nova funcionalidade sem alterar diretamente a branch principal do projeto.

Por exemplo, podemos criar uma branch para desenvolver um novo teste:

Terminal
1
git switch -c teste-login

O comando cria uma nova branch chamada teste-login e muda para ela.

Também podemos listar as branches existentes:

Terminal
1
git branch

🔀 Trocando de branch

Para mudar para uma branch existente:

Terminal
1
git switch main

🔗 Merge

O merge é utilizado para unir as alterações de uma branch em outra.

Imagine que você criou a branch teste-login, desenvolveu os testes e realizou alguns commits. Agora queremos incorporar essas alterações à branch principal.

Primeiro, mudamos para a branch que receberá as alterações:

Terminal
1
2
git switch main
git merge teste-login
💡 Atenção:

Um merge pode gerar conflitos quando as mesmas partes de arquivos foram alteradas de maneiras incompatíveis.

Nesses casos, é necessário analisar e resolver os conflitos antes de concluir o merge.

☁️ Enviando o projeto para o GitHub

Depois de criar um repositório no GitHub, podemos conectar o repositório local ao repositório remoto.

Terminal
1
2
3
git remote add origin https://github.com/usuario/projeto.git
git branch -M main
git push -u origin main

O comando git remote add origin associa o repositório local ao repositório remoto.

O comando git push envia os commits locais para o GitHub.

📥 Pull

O comando git pull busca alterações do repositório remoto e atualiza a branch local.

Terminal
1
git pull
💡 Na prática:

Antes de começar a trabalhar em um projeto compartilhado, é comum atualizar sua branch local para receber as alterações mais recentes.

🔎 Pull Request

Um Pull Request (PR) é uma solicitação para que as alterações de uma branch sejam revisadas e, posteriormente, incorporadas a outra branch.

Um fluxo bastante comum é:

🔄 Fluxo de Pull Request:

1. Criar uma branch.
2. Desenvolver a funcionalidade.
3. Fazer commits.
4. Enviar a branch para o GitHub.
5. Criar um Pull Request.
6. Outros membros revisam o código.
7. Corrigir os pontos encontrados, se necessário.
8. Aprovar o Pull Request.
9. Fazer o merge.

Por exemplo, podemos enviar nossa branch para o GitHub utilizando:

Terminal
1
git push -u origin teste-login

Depois disso, podemos abrir um Pull Request no GitHub solicitando a revisão das alterações.

Outro profissional pode revisar os testes antes que eles sejam incorporados ao projeto principal.

⚠️ Conflitos de merge

Um conflito pode acontecer quando duas branches modificam a mesma parte de um arquivo de maneiras incompatíveis.

Quando isso acontece, o Git indica que existe um conflito que precisa ser resolvido manualmente.

Precisamos escolher qual alteração deve permanecer ou combinar as duas quando isso fizer sentido.

O que você aprendeu:

• git add adiciona alterações à área de preparação.
