Consumindo APIs

Nesta aula, você vai aprender como consumir APIs utilizando Python e a biblioteca requests.

Vamos aprender como fazer requisições HTTP, trabalhar com respostas em JSON, enviar headers e utilizar parâmetros em requisições.

💡 Para lembrar:

Uma API permite que diferentes sistemas troquem informações.

Com Python, podemos enviar uma requisição para uma API, receber uma resposta e utilizar os dados retornados no nosso programa ou em nossos testes.

🌐 O que é uma API?

Uma API é uma interface que permite que um sistema se comunique com outro sistema.

Por exemplo, uma aplicação pode consultar uma API para obter informações sobre usuários, produtos, pedidos ou pagamentos.

📡 Biblioteca requests

A biblioteca requests facilita o envio de requisições HTTP utilizando Python.

Para utilizá-la, primeiro fazemos a importação:

api.py
1
2
3
import requests
resposta = requests.get( "https://api.exemplo.com/usuarios" )

O objeto armazenado em resposta representa a resposta recebida da API.

💡 Principais métodos:

requests.get() → consulta dados.

requests.post() → envia ou cria dados.

requests.put() → atualiza dados.

requests.delete() → remove dados.

🚦 Verificando o status

Depois de fazer uma requisição, podemos verificar o status code da resposta.

status.py
1
2
3
4
5
import requests
resposta = requests.get( "https://api.exemplo.com/usuarios" )
print( resposta.status_code)
🎯 No QA:

O status code é uma das primeiras informações verificadas em um teste de API.

Por exemplo:

200 → requisição processada com sucesso.
201 → recurso criado.
400 → requisição inválida.
404 → recurso não encontrado.
500 → erro no servidor.

📦 Trabalhando com JSON

🧾 Headers

Headers são informações adicionais enviadas junto com a requisição HTTP.

Eles podem informar, por exemplo, o formato dos dados ou informações de autenticação.

headers.py
1
2
3
4
5
6
import requests
headers = {
   "Accept" : "application/json"
}
resposta = requests.get( "https://api.exemplo.com/usuarios" , headers=headers)
💡 Headers comuns:

Accept → informa quais formatos de resposta o cliente aceita.

Content-Type → informa o formato do conteúdo enviado.

Authorization → pode transportar informações utilizadas para autenticação.

🔐 Header de autenticação

Algumas APIs exigem autenticação. Nesse caso, podemos enviar informações de autenticação através de headers.

autenticacao.py
1
2
3
4
5
6
import requests
headers = {
   "Authorization" : "Bearer TOKEN"
}
resposta = requests.get( "https://api.exemplo.com/perfil" , headers=headers)
⚠️ Atenção:

Tokens, senhas e chaves de API não devem ser colocados diretamente no código de um projeto real.

Em projetos reais, prefira variáveis de ambiente ou mecanismos apropriados de gerenciamento de segredos.

🔎 Parâmetros

Algumas APIs permitem enviar parâmetros para especificar melhor uma consulta.

Por exemplo, podemos pesquisar usuários utilizando um nome.

parametros.py
1
2
3
4
5
import requests
params = {
   "nome": "Maria"
}

Depois, passamos o dicionário através do parâmetro params:

busca.py
1
2
3
4
5
params = {
   "nome": "Maria"
}
resposta = requests.get( "https://api.exemplo.com/usuarios" , params=params)
💡 O requests cuida da URL:

Se o parâmetro for nome=Maria, a biblioteca monta os parâmetros da URL automaticamente.

Isso evita a necessidade de montar manualmente toda a query string.

📤 Enviando JSON

Ao enviar dados para uma API, podemos utilizar o parâmetro json do requests para enviar um objeto Python como JSON.

criar_usuario.py
1
2
3
4
5
6
7
8
import requests
usuario = {
   "nome": "Maria",
   "idade": 25
}
resposta = requests.post( "https://api.exemplo.com/usuarios" , json=usuario)
💡 Diferença importante:

params= → normalmente utilizado para parâmetros de consulta.

json= → utilizado para enviar dados no corpo da requisição como JSON.

🧪 Consumindo APIs no QA

O consumo de APIs é muito importante para profissionais de QA e automação de testes.

Podemos verificar não apenas se a requisição funciona, mas também se a resposta contém os dados esperados.

test_api.py
1
2
3
4
5
6
7
8
import requests
resposta = requests.get( "https://api.exemplo.com/usuarios/1" )
assert resposta.status_code == 200
dados = resposta.json()
assert dados[ "id"] == 1
🎯 Pense como QA:

Não basta verificar apenas o status code.

Também podemos validar:

• Estrutura do JSON.
• Valores retornados.
• Headers.
• Tempo de resposta.
• Mensagens de erro.
• Regras de negócio.

📝 Exercício

Imagine uma API que possui o endpoint: /produtos. Crie mentalmente uma requisição para buscar produtos de uma determinada categoria.

Pense nos seguintes elementos:

  • Qual método HTTP utilizar?
  • Qual parâmetro enviar?
  • Qual header poderia ser utilizado?
  • Como acessar o JSON retornado?
  • Qual status code seria esperado em caso de sucesso?
💡 Possível solução:

Utilizar GET para consultar os produtos.

Enviar a categoria através de params.

Utilizar Accept: application/json para indicar que esperamos JSON.

Utilizar response.json() para acessar os dados retornados.

Esperar um status como 200 em uma consulta bem-sucedida.

🧠 Resumo da aula

O que você aprendeu:

• requests facilita o consumo de APIs utilizando Python.
• requests.get() pode ser utilizado para consultar dados.
• requests.post() pode ser utilizado para criar ou enviar dados.
• response.status_code permite verificar o status da resposta.
• response.json() transforma uma resposta JSON em uma estrutura Python.
• Headers transportam informações adicionais na requisição.
• params permite enviar parâmetros de consulta.
• json permite enviar dados no corpo da requisição em formato JSON.
• APIs são muito utilizadas em sistemas modernos e em automação de testes.
• Em QA, podemos validar status, headers, estrutura e conteúdo das respostas.
