Concorrência

Nesta aula, vamos conhecer os principais conceitos de concorrência em Python. Vamos aprender como executar diferentes tarefas de forma concorrente utilizando as bibliotecas threading e multiprocessing.

🎯 Objetivo da aula:

Aprender a executar tarefas concorrentes em Python, entender quando utilizar threads ou processos e construir programas capazes de trabalhar com várias tarefas de forma eficiente.

⚡ O que é concorrência?

Concorrência é a capacidade de um programa lidar com várias tarefas durante o mesmo período de execução.

Isso não significa necessariamente que todas as tarefas estão sendo executadas exatamente ao mesmo tempo. O programa pode alternar entre diferentes tarefas enquanto elas estão sendo executadas.

💡 Exemplo:

Imagine um programa que precisa:

📥 Baixar um arquivo
🌐 Fazer uma requisição HTTP
📊 Processar dados
📝 Salvar um relatório

Em vez de esperar uma tarefa terminar completamente para começar outra, podemos organizar essas tarefas de forma concorrente.

🔄 Concorrência x Paralelismo

Esses dois conceitos são relacionados, mas não são exatamente a mesma coisa.

Concorrência

Várias tarefas progridem de forma intercalada.

Paralelismo

Várias tarefas podem realmente executar ao mesmo tempo, utilizando diferentes núcleos de processamento.

Em Python, threads são muito utilizadas para tarefas que passam bastante tempo esperando, enquanto processos podem ser úteis para tarefas que exigem bastante processamento da CPU.

🧵 1. Threading

O módulo threading permite criar threads, que são fluxos de execução dentro de um processo.

Uma thread pode executar uma função enquanto outra thread executa uma tarefa diferente.

💡 Ideia:

Um processo → várias threads → várias tarefas concorrentes.

🌐 Threading e tarefas de I/O

Threads são especialmente interessantes em tarefas I/O-bound, nas quais o programa passa bastante tempo esperando por operações externas.

Exemplos:

  • Requisições HTTP.
  • Leitura de arquivos.
  • Comunicação com banco de dados.
  • Operações de rede.
💡 Ideia:

Enquanto uma tarefa está esperando uma operação de I/O, outra thread pode continuar trabalhando.

🖥️ 2. Multiprocessing

O módulo multiprocessing permite criar diferentes processos.

Cada processo possui seu próprio espaço de memória e pode executar código independentemente dos outros processos.

Processo

Um programa em execução.

Thread

Um fluxo de execução dentro de um processo.

🧱 Criando um processo

from multiprocessing import Process
def tarefa():
     print( "Executando processo" )
processo = Process(target=tarefa)

processo.join()

🧮 Multiprocessing e CPU

Processos são interessantes para tarefas CPU-bound, ou seja, tarefas que exigem bastante processamento.

Exemplos:

  • Cálculos matemáticos pesados.
  • Processamento de grandes quantidades de dados.
  • Algoritmos computacionalmente intensivos.
  • Processamento de imagens.
💡 Regra geral:

I/O-bound → considere threading.

CPU-bound → considere multiprocessing.

⚖️ Threading x Multiprocessing

threading

🧵 Threads dentro do mesmo processo.
📡 Muito útil para tarefas I/O-bound.
🧠 Compartilham a memória do processo.

multiprocessing

🖥️ Processos separados.
🧮 Útil para tarefas CPU-bound.
🔒 Cada processo possui seu próprio espaço de memória.

🔐 O GIL

Na implementação padrão do Python conhecida como CPython, existe o Global Interpreter Lock (GIL).

De forma simplificada, o GIL limita a execução simultânea de código Python por múltiplas threads dentro de um processo.

💡 Por isso:

Threads continuam sendo muito úteis para operações de I/O, mas para tarefas intensivas de CPU, multiprocessing pode ser uma opção melhor.

🔗 Compartilhando dados

Threads de um mesmo processo podem acessar objetos compartilhados. Isso é conveniente, mas também pode criar problemas quando várias threads modificam os mesmos dados.

⚠️ Cuidado:

Duas threads podem tentar alterar o mesmo recurso ao mesmo tempo. Isso pode gerar uma race condition.

🎯 Quando utilizar cada um?

Use threading quando:

✔ O programa realiza muitas operações de I/O.
✔ Existem tarefas independentes esperando por rede, arquivos ou outros recursos.
✔ Você deseja executar tarefas concorrentes dentro do mesmo processo.

Use multiprocessing quando:

✔ O trabalho exige bastante CPU.
✔ Existem cálculos pesados.
✔ Você deseja aproveitar múltiplos processos.

⚠️ Cuidados com concorrência

Programação concorrente pode tornar um sistema mais eficiente, mas também adiciona complexidade.

  • Race conditions.
  • Deadlocks.
  • Dados compartilhados.
  • Sincronização.
  • Dificuldade de depuração.
💡 Boa prática:

Não utilize concorrência apenas porque ela existe. Primeiro identifique se o problema realmente se beneficia de múltiplas tarefas concorrentes.
