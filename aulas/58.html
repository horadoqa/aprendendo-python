AULA 58

Projeto de automação

Nesta aula, vamos colocar em prática os conceitos aprendidos nas aulas anteriores para construir uma automação web completa utilizando Python. O objetivo é entender como planejar, desenvolver, executar e validar uma automação do início ao fim.

🎯 Objetivo da aula:

Criar uma automação capaz de abrir um navegador, acessar uma aplicação, executar ações, validar resultados e gerar informações sobre a execução.

🛠️ O projeto

Vamos imaginar que precisamos automatizar o teste de um formulário de cadastro. A automação deverá:

  • Abrir o navegador.
  • Acessar a aplicação.
  • Localizar os campos do formulário.
  • Preencher os dados.
  • Enviar o formulário.
  • Validar a resposta da aplicação.
  • Registrar o resultado.
  • Encerrar o navegador.

📋 1. Planejando a automação

Antes de escrever código, precisamos definir exatamente o que queremos automatizar. Um bom projeto de automação começa com um cenário de teste bem definido.

📌 Cenário:

Cadastrar um novo usuário utilizando dados válidos.

Dados:

Nome: Maria
E-mail: maria@example.com
Senha: Teste123

Resultado esperado:

Após o envio do formulário, a aplicação deve apresentar uma mensagem informando que o cadastro foi realizado com sucesso.

from playwright.sync_api import sync_playwright
from dados.usuario import usuario
with sync_playwright() as p:
     navegador = p.chromium.launch( headless= False)
     pagina = navegador.new_page()
     pagina.goto( "https://exemplo.com/cadastro" )
     pagina.locator( "#nome" ).fill(usuario[ "nome" ])
     pagina.locator( "#email" ).fill(usuario[ "email" ])
     pagina.locator( "#senha" ).fill(usuario[ "senha" ])
     pagina.locator( "#cadastrar" ).click()
     mensagem = pagina.locator( "#mensagem" )
     print ( mensagem.text_content() )
     navegador.close()

✅ 6. Validando o resultado

Uma automação de QA não deve apenas executar ações. Precisamos verificar se o resultado obtido é realmente o resultado esperado.

Podemos utilizar uma asserção para validar a mensagem apresentada pela aplicação.

validacao.py

mensagem = pagina.locator( "#mensagem" )
texto = mensagem.text_content()
assert "Cadastro realizado com sucesso" in texto
print ( "Teste aprovado!" )
💡 O que o assert faz?

O assert verifica se uma condição é verdadeira.

Se a condição for verdadeira, o teste continua.

Se for falsa, o Python gera uma exceção, indicando que algo não saiu como esperado.

⚠️ 7. Tratando falhas

Durante uma automação, vários problemas podem acontecer. Um elemento pode não existir, uma página pode demorar para carregar ou o resultado esperado pode não aparecer.

Podemos utilizar try e except para registrar uma falha sem perder informações importantes.

try :
     pagina.goto( "https://exemplo.com" )
     assert pagina.title() == "Cadastro"
     print ( "Teste aprovado!" )
except Exception as erro:
     print ( "Teste falhou:" , erro)
# O erro pode ser registrado para análise posterior.

⭐ 10. Boas práticas de automação

  • Mantenha os testes simples e objetivos.
  • Utilize nomes claros para variáveis e funções.
  • Separe dados de teste do código.
  • Evite repetir código.
  • Utilize seletores estáveis.
  • Evite utilizar sleep() sem necessidade.
  • Valide sempre o resultado esperado.
  • Registre informações importantes da execução.
  • Gere evidências quando fizer sentido.
  • Nunca coloque credenciais reais diretamente no código.

🚀 Desafio da aula

Agora é sua vez de criar uma automação completa. Escolha uma aplicação de teste e desenvolva um fluxo automatizado seguindo as etapas aprendidas.

Sua automação deverá:

  • Abrir o navegador.
  • Acessar a aplicação.
  • Executar pelo menos três ações.

  • Validar pelo menos um resultado.
  • Informar se o teste foi aprovado ou reprovado.
  • Gerar uma evidência caso o teste falhe.
🏆 Desafio extra:

Crie uma pequena suíte de testes com três cenários:

1. Cadastro com dados válidos.
2. Cadastro com e-mail inválido.
3. Cadastro sem preencher um campo obrigatório.

Para cada cenário, defina:

• Dados de entrada.
• Ações realizadas.
• Resultado esperado.
• Resultado obtido.
• Status do teste.
• Evidência em caso de falha.
