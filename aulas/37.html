Projeto de POO

Nesta aula, vamos colocar em prática os principais conceitos de Programação Orientada a Objetos (POO) que aprendemos até aqui. Vamos construir pequenos sistemas utilizando classes, objetos, atributos, métodos, construtores, encapsulamento, herança, polimorfismo e dataclasses.

O objetivo é entender como podemos transformar conceitos do mundo real em estruturas organizadas dentro de um programa Python.

💡 Para lembrar:

Em POO, podemos representar entidades do sistema como objetos.

Por exemplo:

Livro, Usuario, Conta, Cliente e Produto podem ser representados por classes.

Nosso primeiro projeto será um pequeno sistema de biblioteca. O sistema terá livros e usuários e permitirá realizar operações como empréstimo e devolução.

Podemos começar identificando as principais entidades do sistema:

  • Livro — representa um livro disponível na biblioteca.
  • Usuario — representa uma pessoa que pode pegar livros emprestados.

from dataclasses import dataclass
@dataclass
class Livro:
     titulo: str
     autor: str
     disponivel: bool = True
class Usuario:
     def __init__ ( self , nome):
         self .nome = nome
         self .livros = []
     def emprestar( self , livro):
         if livro.disponivel:
             livro.disponivel = False
             self .livros.append(livro)
             return True
         return False
livro = Livro( "Python para QA" , "Maria" )
usuario = Usuario( "João" )
print ( usuario.emprestar(livro))
print ( livro.disponivel)

▶ Resultado

Terminal
> True
> False

Quando o usuário pega o livro emprestado, o atributo disponivel passa a ser False. Assim conseguimos representar o estado do livro dentro do sistema.

class Conta:
     def __init__ ( self , titular):
         self .titular = titular
         self .__saldo = 0
     def depositar( self , valor):
         if valor > 0:
             self .__saldo += valor
     def sacar( self , valor):
         if 0 < valor <= self .__saldo:
             self .__saldo -= valor
             return True
     def consultar_saldo( self ):
         return self .__saldo
conta = Conta( "Maria" )

O saldo fica protegido dentro da classe e o acesso é realizado por meio de métodos. Isso evita que outras partes do programa alterem o saldo diretamente sem passar pelas regras definidas.

🧩 Como pensar em um projeto de POO

Antes de começar a escrever código, podemos identificar as entidades e responsabilidades existentes no problema.

1️⃣ Identifique as entidades

Pergunte:
"Quais objetos existem nesse sistema?"

Exemplo: Cliente, Produto, Pedido.
2️⃣ Defina os atributos

Pergunte:
"Quais informações cada objeto precisa armazenar?"

Um cliente pode ter: nome, email e telefone.
3️⃣ Defina os comportamentos

Pergunte:
"O que esse objeto precisa fazer?"

Uma conta pode: depositar(), sacar() e consultar_saldo().
4️⃣ Crie as regras

Pense nas condições que precisam ser respeitadas.

Por exemplo:
Uma conta não pode realizar um saque maior que o saldo disponível.

🧪 POO aplicada ao QA

Projetos orientados a objetos aparecem com frequência em automação de testes. Podemos criar classes para representar páginas, usuários, produtos, APIs, dados de teste e diferentes componentes da aplicação.

💡 Exemplo:

Em uma automação de login, poderíamos ter uma classe LoginPage com métodos como:

preencher_usuario()
preencher_senha()
clicar_login()
verificar_mensagem()

Dessa forma, o código do teste fica mais organizado e reutilizável.
