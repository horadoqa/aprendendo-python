ORM com SQLAlchemy

Nesta aula, você vai conhecer o conceito de ORM (Object-Relational Mapping) e aprender como utilizar o SQLAlchemy para trabalhar com bancos de dados utilizando objetos Python. Também veremos como criar Models e representar relacionamentos entre diferentes tabelas.

💡 Para lembrar:

ORM significa Object-Relational Mapping.

A ideia é permitir que objetos Python sejam associados a registros de um banco de dados, reduzindo a necessidade de escrever SQL manualmente em todas as operações.

🔄 O que é ORM?

Um ORM é uma técnica que cria uma relação entre objetos da aplicação e tabelas do banco de dados. Em vez de trabalhar diretamente com comandos SQL para todas as operações, podemos utilizar classes e objetos Python.

Exemplo:

Uma classe Python chamada Usuario pode representar uma tabela chamada usuarios.

Cada objeto Usuario pode representar um registro dessa tabela.

⚖️ SQL tradicional x ORM

Utilizando SQL diretamente, podemos escrever uma consulta como:

consulta.sql
1
SELECT * FROM usuarios;

Com um ORM, podemos trabalhar com objetos e métodos Python para realizar operações semelhantes.

💡 Importante:

ORM não elimina a necessidade de conhecer SQL.

Entender SQL continua sendo muito importante, principalmente para QA, análise de dados, debugging e otimização de consultas.

🐍 SQLAlchemy

O SQLAlchemy é uma biblioteca Python bastante utilizada para trabalhar com bancos de dados relacionais. Ela oferece ferramentas para executar SQL e também recursos de ORM.

Para utilizar o SQLAlchemy, podemos instalá-lo utilizando o pip.

1
pip install sqlalchemy

⚙️ Engine

O Engine é responsável por representar a conexão entre o SQLAlchemy e o banco de dados.

Para começar, podemos criar um Engine utilizando create_engine().

💾 Session

A Session é utilizada para interagir com os objetos e persistir alterações no banco de dados. Podemos adicionar objetos, consultar registros, atualizar dados e remover objetos.

from sqlalchemy.orm import Session
from database import engine
from models import Usuario
with Session(engine) as session:
     usuario = Usuario(
         nome= "Maria" ,
         email= "maria@email.com"
     )
     session.add(usuario)
     session.commit()

🔗 Relacionamentos

Bancos relacionais permitem criar relações entre diferentes tabelas. Por exemplo, podemos ter uma tabela de usuários e outra de pedidos. Um usuário pode possuir vários pedidos.

Exemplo:

Usuário 1
├── Pedido 1
├── Pedido 2
└── Pedido 3

Esse é um relacionamento um-para-muitos.

     id: Mapped[int] = mapped_column( primary_key=True)
     usuario_id: Mapped[int] = mapped_column(
         ForeignKey( "usuarios.id" )
     )
     descricao: Mapped[str]

🔄 Relationship

Além da chave estrangeira, o SQLAlchemy permite representar o relacionamento diretamente nos Models utilizando relationship().

from sqlalchemy import ForeignKey
from sqlalchemy.orm import relationship
class Usuario(Base):
     __tablename__ = "usuarios"
     id: Mapped[int] = mapped_column( primary_key=True)
     pedidos = relationship( "Pedido" )
class Pedido(Base):
     __tablename__ = "pedidos"
     id: Mapped[int] = mapped_column( primary_key=True)
     usuario_id: Mapped[int] = mapped_column( ForeignKey( "usuarios.id" ))
🔗 Tipos de relacionamento:

• Um-para-um (1:1)
• Um-para-muitos (1:N)
• Muitos-para-muitos (N:N)

O tipo de relacionamento depende de como os dados da aplicação estão relacionados.

🧪 ORM para QA

Para QA, conhecer ORM é importante porque muitas aplicações modernas utilizam ferramentas como SQLAlchemy para acessar bancos de dados.

Durante testes automatizados, podemos utilizar ORM para criar dados, consultar registros, preparar cenários e validar o estado do banco após uma operação.

Exemplo de fluxo de teste:

1. Criar um usuário através do Model.

2. Salvar o usuário no banco.

3. Executar uma ação na aplicação.

4. Consultar o banco através do ORM.

5. Validar se os dados foram persistidos corretamente.
