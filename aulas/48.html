Autenticação

Nesta aula, você vai aprender os conceitos básicos de autenticação em APIs. Vamos entender como funciona um processo de login, o que são tokens, como funciona o JWT e quais cuidados básicos devemos ter ao proteger uma aplicação.

💡 Para lembrar:

Autenticação responde à pergunta:

"Quem é você?"

Já a autorização responde:

"O que você pode fazer?"

🔐 O que é autenticação?

Autenticação é o processo utilizado para verificar a identidade de uma pessoa ou sistema.

Um exemplo muito comum é o login em uma aplicação. O usuário informa suas credenciais e a aplicação verifica se elas são válidas.

Exemplo:

Usuário: maria

Senha: ********

A aplicação verifica as credenciais e, se estiverem corretas, permite o acesso.

🔄 Fluxo de login

Em uma API, o processo de autenticação normalmente segue algumas etapas:

1. O usuário envia login e senha.

2. A API verifica as credenciais.

3. Se estiverem corretas, a API gera um token.

4. O cliente armazena o token.

5. O token é enviado nas próximas requisições protegidas.

6. A API valida o token antes de permitir o acesso.

@app.post( "/login" )
def login (usuario, senha):

⚠️ Importante:

O exemplo acima é apenas didático.

Em uma aplicação real, nunca devemos armazenar senhas diretamente no código ou compará-las dessa forma.

🎟️ O que são tokens?

Um token é uma informação que pode ser utilizada para representar uma sessão autenticada.

Depois que o usuário realiza o login, a API pode fornecer um token para que ele seja utilizado nas próximas requisições.

Fluxo simplificado:

Login → API valida usuário → Token

Depois:

Token → API → Recurso protegido

📡 Enviando o token

É comum enviar tokens de autenticação no header Authorization.

request.http
1
2
3
GET /produtos
Authorization: Bearer SEU_TOKEN
Bearer indica que o token está sendo enviado como credencial de acesso.

🔑 O que é JWT?

JWT significa JSON Web Token. É um formato utilizado para transportar informações entre sistemas de forma estruturada.

Um JWT possui três partes principais:

Header
Contém informações sobre o token e o algoritmo utilizado.

Payload
Contém informações, chamadas de claims, relacionadas ao token.

Signature
É utilizada para verificar a integridade do token.
Estrutura visual:

HEADER.PAYLOAD.SIGNATURE

🧩 Criando um JWT

Em Python, bibliotecas como PyJWT podem ser utilizadas para trabalhar com JSON Web Tokens.

import jwt

     dados, "chave-secreta" , algorithm= "HS256"

⚠️ Atenção:

Nunca coloque uma chave secreta diretamente no código de uma aplicação real.

Utilize variáveis de ambiente ou um sistema apropriado de gerenciamento de segredos.

🔍 Validando um JWT

Ao receber um token, a aplicação precisa verificar se ele é válido antes de permitir o acesso ao recurso protegido.

import jwt

     token,
     "chave-secreta" ,
     algorithms=[ "HS256" ]
)
print (dados)
💡 Importante:

Decodificar o conteúdo de um JWT não significa, por si só, confiar nele.

A aplicação precisa validar a assinatura e as demais regras de segurança antes de aceitar as informações do token.

🔐 Autenticação x autorização

Esses dois conceitos são importantes e não devem ser confundidos.

Autenticação

Verifica a identidade do usuário.

Autorização

Define quais recursos ou ações aquele usuário pode acessar.
Exemplo:

João fez login corretamente.

Portanto, ele foi autenticado.

Porém, João pode não ter permissão para excluir usuários.

Nesse caso, ele está autenticado, mas não está autorizado a executar essa ação.

🛡️ Segurança básica

Ao criar uma API com autenticação, alguns cuidados são fundamentais.

  • Nunca armazene senhas em texto puro.
  • Utilize algoritmos adequados para armazenamento seguro de senhas.
  • Nunca coloque chaves secretas diretamente no código de produção.
  • Utilize HTTPS para proteger a comunicação.
  • Valide os dados recebidos pela API.
  • Defina tempo de expiração para tokens.
  • Não coloque informações sensíveis dentro do payload do JWT.
  • Controle corretamente as permissões dos usuários.
🚨 Nunca faça isso:

senha = "123456"

ou:

SECRET_KEY = "minha-chave-secreta"

em código de produção.

📡 Status codes relacionados à autenticação

Alguns códigos HTTP aparecem frequentemente em APIs que possuem autenticação.

200 OK
Requisição realizada com sucesso.

201 Created
Um recurso foi criado.

401 Unauthorized
A autenticação é necessária ou as credenciais fornecidas são inválidas.

403 Forbidden
O usuário foi identificado, mas não possui permissão para executar aquela ação.

🧪 Autenticação para QA

Para QA, autenticação gera diversos cenários importantes de teste.

Além do login válido, devemos testar situações como:

  • Login com usuário inexistente.
  • Login com senha incorreta.
  • Campos obrigatórios ausentes.
  • Token ausente.
  • Token inválido.
  • Token expirado.
  • Token alterado.
  • Usuário sem permissão.
  • Acesso a endpoint protegido.
🎯 Pense como QA:

Um endpoint protegido não deve funcionar apenas quando o usuário envia um token válido.

Também precisamos verificar se a API rejeita corretamente tokens inválidos, ausentes ou expirados.

• HTTPS deve ser utilizado para proteger a comunicação.
